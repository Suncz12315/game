# 松鼠大作战 · 手机网页版

把原版 Python/Pygame 的玩法完整搬到了浏览器，并扩展成 **80 个关卡 / 8 个世界**：收集橡果、踩敌人、举起投掷、弹簧、金橡果、尖刺、检查点与连击计分，还加入了 **易碎平台、钥匙藤蔓门、上升气流、巡逻锯轮** 四种新机制。关卡由带种子的生成器产出（同一关号永远是同一张图），覆盖平原、台阶、高塔、断桥、回廊、风井、浮岛七种地形原型，每个世界有独立的天空、远山和树木配色；第 1 关还带逐步推进的新手引导。纯静态 HTML/CSS/JS，不需要构建、不需要后端，手机横竖屏都能玩，并且可以生成成绩卡和挑战链接分享给好友。

```
web/
├── index.html            # 页面结构 / HUD / 菜单 / 弹层 / OG 分享信息
├── style.css             # 响应式布局、触屏按键、安全区适配
├── engine.js             # 纯游戏逻辑（物理、碰撞、关卡、事件）
├── game.js               # 渲染、输入、音效、UI、分享、调试接口
├── sw.js                 # Service Worker（离线缓存）
├── manifest.webmanifest  # PWA 安装信息
├── icons/                # 应用图标与 1200×630 分享预览图
├── tools/                # 图标 / 分享预览图生成页（仅开发用）
├── test.html             # 引擎单元测试（44 项）
└── serve.sh              # 本地一键开服（含局域网地址）
```

## 本地试玩

直接双击 `index.html` 也能玩，但「分享链接」和离线缓存需要 HTTP 环境，推荐起一个本地服务器：

```bash
cd squirrel_fight/web
python3 -m http.server 8080
# 打开 http://localhost:8080
```

或者：

```bash
./serve.sh          # 默认 8080 端口
./serve.sh 9000     # 指定端口
```

脚本会同时打印局域网地址。手机和电脑连同一个 Wi-Fi 后，在手机上打开 `http://<电脑局域网 IP>:8080` 即可试玩。注意：局域网 HTTP 不属于安全上下文，PWA 安装/Service Worker 不可用（游戏本身正常）；分享面板里的「保存图片」「复制链接」仍可用。

## 分享给其他人（部署到公网）

这是一个纯静态站点，把 `web/` 目录里的**全部文件**放到任意静态托管即可。以下方式任选其一：

### 1. Netlify Drop（最快，无需命令行）

1. 打开 <https://app.netlify.com/drop>
2. 把整个 `web` 文件夹拖进去（确保 `index.html` 在站点根目录）
3. 等待上传完成，得到一个 `https://xxx.netlify.app` 地址
4. 把这个地址发给好友即可

### 2. GitHub Pages

1. 新建仓库，把 `web/` 里的内容推到仓库根目录
2. 仓库 **Settings → Pages → Build and deployment** 选择 `Deploy from a branch`
3. 选择 `main` / `/ (root)` 保存
4. 稍等片刻，访问 `https://<用户名>.github.io/<仓库名>/`

### 3. Vercel / Cloudflare Pages

- 导入仓库，Framework Preset 选 **Other / None**，Build Command 留空，Output Directory 填 `.`（或 `web`，取决于仓库结构）
- 部署完成后使用平台提供的域名

### 4. 自己的服务器 / 对象存储

把 `web/` 内容上传到 Nginx、Apache、OSS/COS 等静态站点根目录即可。必须确保：
- 使用 **HTTPS**（PWA、Web Share、剪贴板等能力需要安全上下文）
- `index.html` 可直接作为目录默认页访问
- `.webmanifest` 以 `application/manifest+json`（或至少 `application/json`）返回

### 5. Ubuntu VPS（deploy.sh，按子域名区分游戏）

本游戏域名是 **squirrel.playkk.top**。仓库自带一键脚本，会在服务器上装 nginx、按子域名建独立站点并自动申请 HTTPS 证书：

```bash
cd web
./deploy.sh user@服务器IP        # 默认域名 squirrel.playkk.top
```

前提是域名已解析到服务器 IP。同一台服务器可以托管多个游戏：**每个游戏一个子域名**（如 `squirrel.playkk.top`、`xxx.playkk.top`），每个子域名有独立的站点目录（`/var/www/<域名>`）和 nginx 配置（`/etc/nginx/sites-available/<域名>`），互不影响，可各自反复部署。

### 部署后：让链接预览图正常显示

社交平台（微信、X、Facebook、Slack 等）抓取 OG 信息时不会解析相对路径，因此 `index.html` 里已预置了正式域名的绝对地址：

```html
<meta property="og:image" content="https://squirrel.playkk.top/icons/share-card.png">
<meta property="og:url" content="https://squirrel.playkk.top/">
<link rel="canonical" href="https://squirrel.playkk.top/">
```

如果以后换域名，把这三处一起改掉即可。改完后可用平台自带的调试工具刷新缓存（如 Facebook Sharing Debugger、X Card Validator），微信则需要重新分享或等待缓存过期。

### 更新版本时

改完 `engine.js` / `game.js` / `style.css` 等文件后，把 `sw.js` 顶部的：

```js
const CACHE_VERSION = 'squirrel-quest-v6';
```

改成 `v6`、`v7`…… 同时把 `SHELL` 和 `index.html` 里的 `style.css?v=` / `engine.js?v=` / `game.js?v=` 一起加一，这样已安装 PWA 的用户下次打开会自动换到新缓存。当前版本是 v7（80 关 + 新手引导）。Service Worker 在 `localhost` 下会被刻意跳过，避免本地开发时缓存旧文件；部署到正式域名后自动生效。

## 玩法与操作

| 操作 | 手机 | 键盘 |
|------|------|------|
| 左右移动 | 左下 ◀ ▶ | ← → / A D |
| 跳跃 | 右下「跳」 | 空格 / ↑ / W |
| 举起 / 投掷 | 右下「抓」 | F |
| 暂停 | 右上暂停键 | ESC |

- 收集关卡内**全部普通橡果**即可过关，每个橡果 +50 分
- **金橡果**（带星光的金色橡果）+150 分，属于可选奖励，不要求收集
- 从上方踩敌人 +100 分；举起敌人再投掷命中其他敌人 +200 分
- 120 帧内连续击败敌人会累积连击倍率（最高 ×5），分数直接乘以倍率
- 红色弹簧可以把松鼠弹到高处
- **尖刺**碰到就会掉命，并从最近的**检查点旗帜**重新出发
- **恶魔**（红色带角敌人）移动更快，还会不时蹦跳
- 碰敌人侧面、掉出地图会损失生命；初始 3 条命
- 过关时按剩余生命追加奖励分；最高分与关卡进度保存在浏览器 `localStorage`

### 新增机制

| 元素 | 外观 | 规则 |
|------|------|------|
| **易碎平台** `~` | 带裂纹的灰色石板 | 站上去先晃动约 0.5 秒，然后消失约 2 秒，之后原地恢复；消失期间不能落脚 |
| **藤蔓门** `L` + **钥匙** `K` | 木门缠着藤蔓和锁；金色钥匙 | 收集本关全部钥匙后大门才打开，HUD 会显示 `钥匙 1/2` |
| **上升气流** `W` | 半透明气柱 + 向上箭头 | 进入气流后持续被托起，可以垂直升到柱顶平台，离开后恢复正常重力 |
| **锯轮** `V` / `v` | 旋转锯齿，红色警示光 | 沿水平 / 垂直方向来回巡逻，碰到扣命；巡逻轨迹会画成虚线 |

### 80 个关卡 · 8 个世界

难度从第 1 关到第 80 关平滑递增，橡果与敌人数量逐关不减。每 10 关一个世界，逐步引入新机制；所有普通橡果、钥匙、金橡果与检查点都经过跳跃图 BFS 可达性校验（80/80 通过），任意两关布局的行模式相似度低于 0.5。

| 世界 | 关卡 | 名称 | 机制与视觉 |
|------|------|------|------------|
| 1 | 1–10 | 林间 | 纯跳跃入门 → 弹簧 → 尖刺 → 易碎平台 + 第一把钥匙；白天林间、春日蓝天与秋色林地轮换 |
| 2 | 11–20 | 弹簧高塔 | 弹簧与易碎平台为主，塔身逐关变高；蓝天、云海与高空配色 |
| 3 | 21–30 | 藤蔓迷径 | 钥匙藤蔓门、荆棘长廊与易碎桥组合；深绿密林和藤影暗绿两套配色 |
| 4 | 31–40 | 风之峡谷 | 上升气流竖井 + 锯轮 + 尖刺，峡谷逐关变宽变深；落日、雷暴与月夜 |
| 5 | 41–50 | 黄金终局 | 全机制综合试炼，金橡果收尾；金色树冠、秋叶与星空王座 |
| 6 | 51–60 | 暮色洞窟 | `@` 砖石洞窟、低天花板回廊、锯轮迷阵；暗蓝紫岩洞配色 |
| 7 | 61–70 | 云海之巅 | 浮岛链为主、少地面，气流与易碎平台组合；高空亮白蓝配色 |
| 8 | 71–80 | 星夜王庭 | 全机制高难度综合试炼，恶魔与锯轮密度最高；紫金星空配色 |

各世界的关卡名与布局都是独立生成的（80 个名称、80 份布局互不重复），后期关卡的机制数量明显多于前 10 关。第 8 关 / 第 38 关 / 第 48 关等夜景、以及黄金世界的暖光都是通过关卡主题实时绘制的，不额外加载图片。

### 第 1 关新手引导

首次进入第 1 关时，画面顶部会出现 5 步引导，完成一步自动进入下一步：

1. 左右移动
2. 跳跃
3. 收集橡果
4. 从上方踩扁敌人
5. 收齐全部橡果过关

移动按累计位移判定，跳跃 / 橡果 / 踩敌监听引擎事件，因此顺序可以乱（先吃到橡果也会被记住）。右上角「跳过」会关闭引导并记住选择；完成全部步骤后也不会再打扰。手机上的提示文案会自动改成「按住 ◀ ▶」「点『跳』」等触屏说法。

主菜单的「选择关卡」会按进度解锁：通过一关解锁下一关，点亮的关卡可以直接重玩。首次游玩从第 1 关开始，之后点「开始游戏」会从已解锁的最高关继续。80 个关卡按钮按 8 个世界用不同底色区分。

### 分享与挑战

游戏内「分享给好友 / 分享成绩」会：

1. 生成一张 1080×1350 的成绩卡（可保存为图片）
2. 生成带 `?c=<分数>` 的挑战链接
3. 支持系统分享面板（Web Share API，含图片文件）；不支持时回退为「复制链接 / 保存图片」

好友打开挑战链接后，主菜单会显示「好友向你发起挑战：X 分」，通关结算时会提示是否超过或追平该分数。

### 调试用 URL 参数

| 参数 | 作用 |
|------|------|
| `?play=1` | 打开页面后自动开始第 1 关 |
| `?play=1&level=42` | 自动开始第 42 关（1–80） |

## 兼容性与已知限制

- **iOS Safari**：非视频元素无法真正全屏，PWA 会以独立窗口运行；`navigator.share` 对文件的支持因系统版本而异，已提供保存图片/复制链接兜底。
- **音效**：浏览器要求用户手势后才能启动 Web Audio；首次点击「开始游戏」后才会出声。
- **剪贴板**：无 HTTPS 或旧浏览器会回退到 `execCommand`，再失败时提示手动长按复制。
- **分享预览**：必须把 `og:image` 改成公网绝对地址，社交平台才会显示 1200×630 卡片。
- **离线缓存**：需要 HTTPS（或 localhost）；用 `file://` 直接打开时不会注册 Service Worker。
- **进度存本地**：最高分与已解锁关卡只存在当前浏览器，没有服务端排行榜；挑战分数通过链接传递，不依赖服务器。

## 与 Python 原版的关系

- `engine.js` 是 `game_engine.py` 的 JavaScript 移植，基础物理与计分规则保持一致
- 80 个网页关卡由带种子的生成器产出（7 种地形原型 + 指纹防雷同），经过可达性校验，分成 8 个世界，与原版 3 关的布局不同
- 金橡果、尖刺、检查点、连击倍率与恶魔跳跃是网页版扩展内容
- `game.js` 对应 `main_game.py` 的表现层，但重新实现了移动端布局、触屏输入、PWA 与分享能力
- 原版仍可运行：`python main_game.py`（需要 pygame / pygame-ce），原版仍为 3 个关卡
